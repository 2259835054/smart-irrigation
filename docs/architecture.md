# 系统架构设计文档

## 文档概述

本文档详细描述了基于 ESP32 的多通道智能灌溉系统的架构设计，包括硬件架构、软件架构、模块关系以及数据流。

## 2. 硬件架构

### 2.1 核心处理器

**ESP32-WROOM-32**

- **双核处理器**：Xtensa LX6，主频 240MHz
- **内存**：520KB SRAM，4MB Flash
- **无线通信**：WiFi 802.11 b/g/n，蓝牙 4.2
- **外设接口**：GPIO、ADC、LEDC、I2C、SPI、UART

### 2.2 传感器模块

| 传感器 | 型号 | 接口类型 | GPIO | 功能 |
|--------|------|---------|------|------|
| 土壤湿度通道1 | 电容式 | 模拟 ADC | GPIO 34 | 测量土壤湿度 0-100% |
| 土壤湿度通道2 | 电容式 | 模拟 ADC | GPIO 35 | 测量土壤湿度 0-100% |
| 土壤湿度通道3 | 电容式 | 模拟 ADC | GPIO 32 | 测量土壤湿度 0-100% |
| 土壤湿度通道4 | 电容式 | 模拟 ADC | GPIO 33 | 测量土壤湿度 0-100% |
| 温湿度传感器 | DHT22 | 数字单总线 | GPIO 4 | 测量环境温度和湿度 |
| 光照传感器 | BH1750/光敏电阻 | I2C/模拟 | GPIO 36 | 测量光照强度 |
| 水位传感器 | 浮球开关 | 数字开关 | GPIO 5 | 检测水箱水位 |

**关键特性**：
- **滑动窗口中值滤波**：每个土壤湿度通道采集 10 个样本，取中值抑制噪声
- **校准功能**：支持干燥值和湿润值校准，适配不同传感器
- **故障检测**：自动检测传感器断线或异常读数

### 2.3 执行器模块

| 执行器 | 型号 | 接口类型 | GPIO | 功能 |
|--------|------|---------|------|------|
| 水泵通道1 | 5V 潜水泵 | PWM（LEDC） | GPIO 16 | 灌溉控制，PWM 调速 |
| 水泵通道2 | 5V 潜水泵 | PWM（LEDC） | GPIO 17 | 灌溉控制，PWM 调速 |
| 水泵通道3 | 5V 潜水泵 | PWM（LEDC） | GPIO 18 | 灌溉控制，PWM 调速 |
| 水泵通道4 | 5V 潜水泵 | PWM（LEDC） | GPIO 19 | 灌溉控制，PWM 调速 |
| LED 指示灯 | 5mm LED | 数字输出 | GPIO 2 | 系统状态指示 |
| 蜂鸣器 | 有源蜂鸣器 5V | 数字输出 | GPIO 23 | 报警提示 |

**MOS 管驱动电路**：
- 每个水泵通过 IRF520/IRF540 MOS 管驱动
- ESP32 PWM 信号控制 MOS 管开关
- 水泵独立 5V 供电，与 ESP32 共地

### 2.4 人机交互模块

| 模块 | 型号 | 接口 | GPIO | 功能 |
|------|------|-----|------|------|
| OLED 显示屏 | SSD1306 0.96" | I2C | SDA=21, SCL=22 | 显示传感器数据、系统状态 |
| 模式按键 | 轻触开关 | 数字输入 | GPIO 15 | 切换灌溉模式 |
| 选择按键 | 轻触开关 | 数字输入 | GPIO 13 | 确认/选择操作 |

### 2.5 电源架构

```
┌─────────────────┐
│  5V 3A 适配器   │
└────────┬────────┘
         │
    ┌────┴─────┐
    │          │
    ↓          ↓
┌────────┐  ┌──────────┐
│ ESP32  │  │ 4x 水泵   │
│(板载   │  │(MOS 驱动) │
│ AMS1117│  │          │
│ 3.3V)  │  │          │
└────────┘  └──────────┘
    │
    ↓
┌──────────────────┐
│  传感器 & 外设    │
│  (3.3V 供电)     │
└──────────────────┘
```

**供电方案**：
- **ESP32**：由板载 AMS1117 稳压器提供 3.3V
- **水泵**：直接使用 5V 供电（通过 MOS 管控制）
- **传感器**：DHT22、OLED 使用 3.3V，部分模拟传感器使用 5V
- **总功耗**：待机约 0.5W，4 泵全开约 8W

## 3. 软件架构

### 3.1 分层设计

系统采用经典的**五层架构**，自底向上分别为：

1. **硬件抽象层（HAL）**：ESP32 Arduino Core 提供的底层 API
2. **驱动层**：传感器驱动、PWM 驱动、存储驱动
3. **业务逻辑层**：PID 算法、安全保护、数据滤波
4. **应用层**：灌溉控制、显示管理、数据记录
5. **通信层**：Web Server、MQTT、OTA

### 3.2 模块划分

| 模块名称 | 文件 | 代码行数 | 主要职责 |
|---------|------|---------|---------|
| **配置管理** | config.h | 112 | 全局常量、引脚定义、参数配置 |
| **传感器模块** | sensors.h/.cpp | 412 | 7 种传感器数据采集、滤波 |
| **灌溉控制** | irrigation.h/.cpp | 520 | 4 种模式灌溉逻辑、PWM 控制 |
| **PID 控制器** | pid_controller.h/.cpp | 187 | PID 算法（增量式/位置式） |
| **显示模块** | display.h/.cpp | 777 | OLED 6 页面 UI、图表绘制 |
| **网络模块** | network.h/.cpp | 1222 | Web Server、8 个 REST API |
| **MQTT 客户端** | mqtt_client.h/.cpp | 678 | MQTT 发布/订阅 |
| **数据记录** | data_logger.h/.cpp | 650 | LittleFS 文件读写、JSON |
| **按键处理** | button.h/.cpp | 235 | 状态机消抖、短按/长按 |
| **电源管理** | power_manager.h/.cpp | 189 | Deep Sleep 低功耗 |
| **RTOS 任务** | rtos_tasks.h/.cpp | 1121 | 8 个任务、同步机制 |
| **主程序** | smart_irrigation.ino | 245 | setup/loop 入口 |

### 3.3 FreeRTOS 任务架构

系统运行 **8 个并发任务**，分别绑定到 ESP32 的两个核心：

**Core 0（传感器核心，4 个任务）**：
- **TaskSensor**（优先级3，周期3秒）：传感器数据采集
- **TaskIrrigation**（优先级4，周期1秒）：灌溉控制逻辑
- **TaskButton**（优先级3，周期50毫秒）：按键扫描
- **TaskWatchdog**（优先级5，周期5秒）：系统监控

**Core 1（通信核心，4 个任务）**：
- **TaskDisplay**（优先级1，周期500毫秒）：OLED 更新
- **TaskNetwork**（优先级2，周期100毫秒）：Web Server
- **TaskMQTT**（优先级2，周期10秒）：MQTT 通信
- **TaskDataLog**（优先级1，周期60秒）：数据记录

**同步机制**：
- **互斥量（Mutex）**：保护共享传感器数据
- **队列（Queue）**：传递命令和按键事件
- **事件组（EventGroup）**：WiFi/MQTT 连接状态同步

## 6. 各模块职责说明

### 6.1 传感器模块（sensors）

**职责**：
- 初始化所有传感器硬件
- 定期采集传感器原始数据
- 应用滑动窗口中值滤波算法
- 校准数据并转换为物理量（百分比、摄氏度等）
- 检测传感器故障

**输入**：物理信号（ADC 电压、数字脉冲）
**输出**：`SensorData` 结构体（湿度、温度、光照等）

### 6.2 灌溉控制模块（irrigation）

**职责**：
- 实现 4 种灌溉模式（PID、简单阈值、定时、手动）
- 控制 4 路水泵的 PWM 输出
- 执行安全保护逻辑（超时、冷却、缺水）
- 处理控制命令队列
- 维护灌溉统计数据（浇水次数、累计时间）

**输入**：传感器数据、控制命令
**输出**：PWM 信号（GPIO 16/17/18/19）

### 6.3 PID 控制器（pid_controller）

**职责**：
- 实现标准 PID 算法（比例、积分、微分）
- 支持增量式和位置式两种模式
- 抗积分饱和处理
- 可配置 PID 参数（Kp、Ki、Kd）

**输入**：设定值（目标湿度）、当前值（实际湿度）
**输出**：控制量（PWM 值 0-255）

### 6.4 显示模块（display）

**职责**：
- 初始化 OLED 显示屏（SSD1306）
- 实现 6 个页面的 UI 渲染
- 绘制数据图表（湿度曲线、温度曲线）
- 处理页面切换逻辑

**页面列表**：
1. 主页面（系统状态、IP 地址）
2. 传感器数据页（4 路湿度、温湿度）
3. 灌溉状态页（水泵运行状态、PWM）
4. 历史图表页（湿度趋势）
5. 系统信息页（运行时间、内存）
6. 配置页面（阈值设置）

### 6.5 网络模块（network）

**职责**：
- 连接 WiFi 网络
- 启动 Web Server（端口 80）
- 实现 8 个 REST API 端点
- 提供响应式 Web 界面（HTML + JS）
- OTA 固件升级功能

**API 端点**：
- `GET /api/status` — 系统状态
- `GET /api/history` — 历史数据
- `POST /api/control` — 水泵控制
- `POST /api/mode` — 模式切换
- `POST /api/threshold` — 阈值设置
- `GET /api/system` — 系统信息
- `POST /api/reboot` — 重启
- `POST /update` — OTA 升级

### 6.6 MQTT 客户端（mqtt_client）

**职责**：
- 连接 MQTT Broker（broker.emqx.io）
- 定期发布传感器数据（10 秒间隔）
- 订阅控制命令主题
- 处理 MQTT 消息并转换为内部命令

**主题设计**：
- 发布：`home/irrigation/sensors`、`home/irrigation/status`
- 订阅：`home/irrigation/control`、`home/irrigation/mode`

### 6.7 数据记录模块（data_logger）

**职责**：
- 初始化 LittleFS 文件系统
- 定期记录传感器数据到 JSON 文件（每分钟）
- 保存和加载配置参数
- 提供历史数据查询接口
- 文件循环覆盖（保留最近 24 小时）

**文件结构**：
- `/data_log.json` — 传感器历史数据
- `/config.json` — 系统配置参数

### 6.8 按键处理模块（button）

**职责**：
- 扫描 2 个按键的输入状态
- 实现状态机消抖算法
- 识别短按、长按、双击事件
- 发送按键事件到队列

**按键功能**：
- 模式按键：短按切换模式，长按进入配置
- 选择按键：短按翻页，长按确认

### 6.9 电源管理模块（power_manager）

**职责**：
- 检测电池电压（可选）
- 进入 Deep Sleep 模式
- 配置唤醒源（定时器、GPIO）
- 低电量保护

**节能策略**：
- 无操作 5 分钟后自动休眠
- Deep Sleep 期间功耗 < 10μA
- 定时唤醒采集数据并浇水

### 6.10 RTOS 任务模块（rtos_tasks）

**职责**：
- 初始化 FreeRTOS 同步对象（互斥量、队列、事件组）
- 创建 8 个任务并绑定到指定核心
- 提供任务间通信接口
- 监控任务运行状态（看门狗）

## 7. 设计原则

### 7.1 模块化设计

- **高内聚**：每个模块职责单一明确
- **低耦合**：模块间通过接口通信，减少依赖
- **可测试**：每个模块可独立测试

### 7.2 实时性保证

- 传感器采集任务优先级较高（3）
- 灌溉控制任务最高优先级（4）
- 看门狗任务最高优先级（5）
- 通信任务优先级较低（1-2）

### 7.3 安全性设计

- 多重安全保护（超时、缺水、冷却）
- 互斥量保护共享资源
- 看门狗检测任务死锁
- OTA 升级失败自动回滚

### 7.4 可扩展性

- 通道数可配置（`NUM_CHANNELS`）
- 传感器类型可替换
- 灌溉模式可扩展
- API 可增加新端点

## 9. 总结

本系统采用**分层模块化架构**，通过 FreeRTOS 实现多任务并发，保证了系统的**实时性、可靠性和可扩展性**。硬件上采用 ESP32 双核处理器，充分利用双核优势，将传感器密集型任务和通信密集型任务分离。软件上使用面向对象设计思想，各模块职责清晰，耦合度低，便于维护和扩展。

整体架构兼顾了**性能**（实时响应）、**功能**（多模式控制）和**用户体验**（Web/MQTT/本地三种交互方式），是一款**毕业设计级别**的完整嵌入式物联网系统。
